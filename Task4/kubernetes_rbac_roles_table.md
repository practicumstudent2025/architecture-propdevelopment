# Таблица ролей Kubernetes для PropDevelopment

## Обоснование ролевой модели

На основе анализа заданий 1-3 выявлены следующие группы пользователей PropDevelopment:

**Технические роли:**
- **Администраторы ИБ** - полный доступ к кластеру
- **DevOps-инженеры** - управление инфраструктурой
- **Разработчики** - развертывание и управление приложениями
- **Аналитики данных** - доступ к данным и мониторингу

**Бизнес-роли:**
- **Бухгалтеры** - доступ к финансовым данным
- **Менеджеры** - мониторинг бизнес-процессов
- **Аналитики BI** - анализ данных и отчётность

**Операционные роли:**
- **Операционные команды** - мониторинг и просмотр ресурсов
- **Специалисты поддержки клиентов** - работа с клиентскими сервисами
- **Специалисты поддержки собственников** - работа с сервисами ЖКУ

**Внешние роли:**
- **Партнёры Smart Home** - интеграция с внешними системами
- **Внешние интеграторы** - API доступ к системам

| Роль | Права роли | Группы пользователей |
| --- | --- | --- |
| **cluster-admin** | • Полный доступ ко всем ресурсам кластера<br>• Создание, изменение, удаление любых ресурсов<br>• Доступ к секретам и конфигурациям<br>• Управление RBAC<br>• Доступ к метрикам и логам<br>• Управление узлами кластера | • Специалист по ИБ<br>• Руководитель IT-команды<br>• Главный DevOps-инженер |
| **namespace-admin** | • Полный доступ к ресурсам в назначенных namespace<br>• Создание, изменение, удаление ресурсов в namespace<br>• Доступ к секретам в namespace<br>• Управление ConfigMaps<br>• Создание и управление ServiceAccounts | • DevOps-инженеры доменов<br>• Ведущие разработчики продуктовых команд |
| **developer** | • Создание и управление Deployment, Service, Ingress<br>• Доступ к логам приложений<br>• Создание ConfigMaps и Secrets (только в назначенных namespace)<br>• Просмотр статуса Pods и Services<br>• Управление ReplicaSets и DaemonSets | • Разработчики функциональных команд<br>• Инженеры по эксплуатации |
| **data-analyst** | • Чтение данных из баз данных<br>• Доступ к метрикам и логам<br>• Просмотр ConfigMaps с конфигурацией БД<br>• Доступ к Service endpoints<br>• Просмотр PersistentVolumes | • Аналитики BI<br>• Бизнес-аналитики<br>• Специалисты по данным |
| **monitor-viewer** | • Просмотр всех ресурсов кластера (только чтение)<br>• Доступ к метрикам и логам<br>• Просмотр статуса Pods, Services, Deployments<br>• Доступ к событиям кластера<br>• Просмотр ConfigMaps и Secrets (без содержимого) | • Операционные команды<br>• Менеджеры продуктов<br>• Специалисты поддержки |
| **security-auditor** | • Просмотр всех ресурсов кластера<br>• Доступ к событиям безопасности<br>• Просмотр RBAC конфигураций<br>• Доступ к логам аутентификации<br>• Просмотр сетевых политик | • Специалист по ИБ<br>• Аудиторы безопасности<br>• Compliance специалисты |
| **smart-home-operator** | • Управление Pods и Services в namespace smart-home<br>• Доступ к IoT конфигурациям<br>• Управление ConfigMaps для устройств<br>• Просмотр логов IoT сервисов<br>• Управление Secrets для IoT аутентификации | • Операторы Smart Home<br>• Технические специалисты IoT<br>• Специалисты по интеграции |
| **accountant** | • Доступ к финансовым данным в namespace finance<br>• Просмотр логов финансовых сервисов<br>• Доступ к ConfigMaps с финансовыми конфигурациями<br>• Просмотр метрик финансовых операций<br>• Доступ к Service endpoints финансовых сервисов | • Бухгалтеры<br>• Финансовые аналитики<br>• Специалисты по финансовому учёту |
| **manager** | • Просмотр статуса приложений в назначенных namespace<br>• Доступ к метрикам производительности<br>• Просмотр логов бизнес-процессов<br>• Доступ к дашбордам мониторинга<br>• Просмотр событий кластера | • Менеджеры продаж<br>• Менеджеры продуктов<br>• Руководители доменов |
| **client-support** | • Просмотр логов клиентских приложений<br>• Доступ к метрикам клиентских сервисов<br>• Просмотр статуса клиентских Pods<br>• Доступ к событиям клиентских namespace<br>• Просмотр ConfigMaps клиентских конфигураций | • Специалисты поддержки клиентов<br>• Операторы клиентского сервиса<br>• Технические консультанты |
| **owner-support** | • Просмотр логов сервисов для собственников<br>• Доступ к метрикам tenant сервисов<br>• Просмотр статуса сервисов ЖКУ<br>• Доступ к событиям tenant namespace<br>• Просмотр конфигураций Smart Home | • Специалисты поддержки собственников<br>• Операторы ЖКУ<br>• Технические специалисты Smart Home |
| **external-partner** | • Ограниченный доступ к API endpoints<br>• Просмотр статуса интеграционных сервисов<br>• Доступ к логам интеграций<br>• Просмотр метрик партнёрских сервисов<br>• Доступ к событиям интеграционных namespace | • Партнёры Smart Home<br>• Внешние интеграторы<br>• API потребители |

## Namespace структура

```
propdevelopment/
├── sales/           # Группа сервисов для продаж
├── tenant-services/ # Группа сервисов ЖКУ
├── finance/         # Финансовый домен
├── data/           # Дата группа сервисов
├── smart-home/     # Smart Home сервисы
├── monitoring/     # Системы мониторинга
└── security/       # Системы безопасности
```

## Принципы безопасности

1. **Принцип минимальных привилегий** - пользователи получают только необходимые права
2. **Разделение обязанностей** - критические операции требуют нескольких ролей
3. **Аудит доступа** - все действия логируются
4. **Временные права** - доступ предоставляется на ограниченное время
5. **Регулярный пересмотр** - роли пересматриваются ежеквартально

## Соответствие требованиям безопасности

- **ФЗ-152** - контроль доступа к персональным данным
- **ISO/IEC 27001** - управление доступом к информационным системам
- **RBAC принципы** - ролевая модель управления доступом
- **Kubernetes Security Best Practices** - рекомендации по безопасности кластера
